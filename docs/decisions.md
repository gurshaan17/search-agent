## Phase 3: Persistence and recall (2026-11-11)
**Decided:** Use the installed better-sqlite3 dependency with WAL, timestamped turns, saved sources/search logs, and an external-content FTS5 index maintained by insert/update/delete triggers. Auto-create `data/chat.sqlite`. Each CLI run starts a conversation; `CLI_USER_ID` (default `local`) scopes recall across sessions. Save questions before generation and preserve available evidence on failure. Failed generations with partial text are marked interrupted.
**Why:** Code-side recall preserves the single `web_search` tool and adds no model round-trip. chrono-node resolves English dates against the request time and local timezone offset. Convert each local midnight separately to UTC for DST. Past weekday correction prevents bare weekdays selecting future history. Rank topic matches within seven days ahead of date-only results; include up to six question/reply pairs, timestamps, sources, and a change-check hint, with answers capped at 2000 characters.
**Considered and rejected:** Vector storage and a recall tool add unnecessary infrastructure or violate the one-tool constraint. A fixed 24-hour day is incorrect across DST. Current conversation SDK messages stay in memory; persisted recall supplies selected older turns rather than replaying every previous conversation.
**Measured:** Typecheck and all 16 tests pass. Eight new tests exercise local-day UTC bounds, past weekdays, a 25-hour New York DST day, topic/date ranking, cross-conversation recall and user isolation, empty recall, missing replies and half-open day boundaries, and database reopen with FTS. Live Gemini CLI answered the CAP question without any search events, then a separate CLI invocation for `phase3-verification` recalled “explain the CAP theorem in two sentences” correctly, also without searching. This verifies live persistence and context injection across sessions. The first sandboxed attempt failed; network-enabled runs succeeded.
**Risks / unknowns:** CLI identity is a local namespace, not authentication. English date parsing and the system timezone are the current interface. FTS candidates are bounded to 100 per lookup. Broader temporal policy and hostile-history hardening remain later-phase work. Phase 2's Node.js and three-provider pricing live prompts remain unverified; the owner authorized proceeding to Phase 3. Phase 1 timeout evidence remains unchanged.

## Phase 5: Server, streaming, UI (2026-11-11)
**Decided:** Replace the scaffold HTTP server with Hono and its Node adapter, serving a single static HTML page and POST /chat SSE. The app factory shares the existing agent, context builder, and SQLite store. Reloaded browser sessions reuse localStorage user/conversation IDs and load the latest 40 conversation messages from SQLite. New chat rotates the conversation ID while retaining the memory owner. The local server binds to 127.0.0.1.
**Why:** A single server and buildless frontend keep setup simple. Serialize writes from concurrent search callbacks so SSE frames stay intact. Forward disconnect/Stop cancellation through the agent to search requests, and persist available evidence plus explicit interruption markers. Reject overlapping turns within one conversation to preserve question/reply ordering. Build formatting and citation links from DOM nodes and textContent; never interpret generated text as HTML. Only HTTP/HTTPS links are allowed.
**Considered and rejected:** A frontend framework, markdown parser dependency, hosted service, and new authentication system exceed this phase. The page supports a small safe subset: headings, bold, inline/code blocks, bullets, tables, links, and numbered citations, including grouped citations. Sources use per-answer anchor IDs so repeated source numbers remain distinct across turns.
**Measured:** Typecheck, all 23 tests, and diff checks pass. Four HTTP/SDK tests cover SSE ordering, sources and persistence, reload context and user isolation, invalid requests, generic errors, disconnect cancellation, and overlapping turns. Browser acceptance with a temporary Playwright installation and isolated headless Chrome passed: real Gemini/Exa Node.js lookup, streamed answer, eight working citation links, reload and accurate earlier-question recall, New chat, 390px mobile width with no overflow, safe rendering of hostile model/source strings, and no page errors. Separate mobile rendering checks cover lists, tables and literal code blocks. Screenshots inspected at desktop and mobile sizes. A clean source snapshot (no .env, runtime data, or existing dependencies) passed npm ci, typecheck, all 23 tests, npm run dev startup on port 3001, and /health. Fresh startup used mock search and a dummy Gemini key without calling the model. Real browser requests used the original local server and local credentials.
**Risks / unknowns:** Browser user IDs are local namespaces, not authentication; clearing browser storage loses the identity association. The latest 40 messages are restored for model context; the visible transcript starts empty after reload. Full citation validation, rate limiting, and broader failure hardening remain Phase 7. Browser testing used Chrome because the session browser-control execution tool was unavailable. Temporary screenshots and test scripts are under /tmp; no browser dependency was added to the project. npm warned about dependency install scripts, but native SQLite and all tests worked in the clean install.
