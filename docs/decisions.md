## Phase 3: Persistence and recall (2026-11-11)

Auto-create `data/chat.sqlite`. Each CLI run starts a conversation; `CLI_USER_ID` (default `local`) scopes recall across sessions. Save questions before generation and preserve available evidence on failure. Failed generations with partial text are marked interrupted.
**Why:** Code-side recall preserves the single `web_search` tool and adds no model round-trip. chrono-node resolves English dates against the request time and local timezone offset. Convert each local midnight separately to UTC for DST. Past weekday correction prevents bare weekdays selecting future history. Rank topic matches within seven days ahead of date-only results; include up to six question/reply pairs, timestamps, sources, and a change-check hint, with answers capped at 2000 characters.
**Considered and rejected:** Vector storage and a recall tool add unnecessary infrastructure or violate the one-tool constraint. A fixed 24-hour day is incorrect across DST. Current conversation SDK messages stay in memory; persisted recall supplies selected older turns rather than replaying every previous conversation.

## Phase 5: Server, streaming, UI (2026-11-11)

The app factory shares the existing agent, context builder, and SQLite store. The local server binds to 127.0.0.1.
**Why:** A single server and buildless frontend keep setup simple. Serialize writes from concurrent search callbacks so SSE frames stay intact. ## Phase 7: Hardening (2026-11-12)
**Decided:** Add incremental, code-aware citation validation shared by browser and CLI output: normalize known source prefixes, validate grouped/split references, flag unmapped or interrupted numeric references, and save validated text. Enforce a 64 KiB HTTP body cap and a shared 20,000-character question limit, retain model/search/output budgets, and add a bounded per-process socket-IP limiter (20 requests per 60 seconds, 429 plus Retry-After). Ignore forwarded-IP headers. Log one allowlisted metrics record per admitted turn; omit query/prompt/source text, IPs, headers, upstream errors, and raw provider usage. Suppress the SDK default error dump.
**Why:** References must be checked before they are displayed, including when token chunks split them; code literals must survive intact. Early body/rate rejection avoids unnecessary model calls and persistence. Keep failed, empty, and excerpt-free search results explicit, continue usable items, and offer narrower queries rather than inventing details. Treat truncation, transport errors and cancellation as incomplete generation, preserve available evidence, and keep browser recovery controls usable.
**Considered and rejected:** A distributed rate-limit store, authentication redesign, extra model, new dependency, and full markdown parser exceed this local-app hardening phase. Citation membership cannot establish semantic claim support. The CLI retains plain validated user/assistant messages rather than replaying raw SDK tool transcripts and logs only status metadata plus turn metrics.
**Measured:** Typecheck, all 40 offline tests, and diff checks pass. The focused injection/failure/empty/poor evidence evals passed 4/4; the full real-Gemini/mock-search gate passed 14/14 with zero invalid raw citations in that run. Tests cover split and grouped citations, source-prefix normalization, code literals, malformed endings, persistence of validated output, body/message rejection, per-IP quotas and expiry, forwarded-header bypass attempts, bounded limiter state, log privacy and suppression of raw SDK errors, truncation, transport failure after partial text, and existing cancellation/budgets. A disposable Chrome browser against an isolated in-memory server passed an actual TCP-drop test mid-reply: partial answer retained, explicit connection-loss/retry guidance shown, composer unlocked, New chat recovered, no page errors. The browser offline toggle did not terminate the existing localhost stream, so it was not treated as proof; the owned test server's TCP connections were cut instead. Raw gate output is in docs/evals/phase7-gate.json. Temporary browser proof: /tmp/phase7-network-loss.png.
**Risks / unknowns:** Model behavior remains probabilistic; passing fixtures do not guarantee all possible injection attempts or factual claims are handled correctly. Citation validation checks membership, not attribution. Empty/poor evidence honesty is instructed and evaluated, not a semantic fact checker. Rate limits are local to one process and direct connection IP; browser IDs remain local namespaces rather than authenticated identity. Provider token usage can be unavailable on errors. Existing live latency limitations remain. No Phase 8 work was started.
